Networks from scratch

In Lesson 01 loss.backward() was a black box that filled in .grad. This lesson opens the box. Seven numbers, one calculator, and every gradient in a small network worked out by hand. 02 · 1One neuron, three moves

A neural network is made of one part, repeated. That part does three things, in a fixed order: multiply, add, bend.

  1. Multiply. Each incoming number is multiplied by its own weight.
  2. Add. The products are summed, and one extra number called the bias is added on top.
  3. Bend. The result passes through a non-linear function — anything whose graph is not a straight line, so that doubling the input does not simply double the output.

The usual bend is ReLU, short for rectified linear unit. It is just max(0, x): keep a positive number, replace anything else with zero. Its slope is 1 on the right of zero and 0 on the left. That flat left half looks harmless. Two sections from now it kills a unit, so hold on to it.

Steps 1 and 2 together are a dot product plus a constant. A layer of 128 neurons does 128 of these at once, which is why a layer is a matrix multiply and not a loop. The bias matters more than it looks: without it, every neuron is forced to make its decision around zero, and the layer can only rotate and stretch the input, never shift it.

Said another way: a layer's weights decide which combinations of the inputs are interesting, and the bias decides how much evidence is needed before the neuron speaks. Both are learned. Nothing else in the layer is.

02 · 2Backpropagation, with real numbers

Autograd is fine until it hands you a gradient that looks wrong. Then you need to work out the right answer yourself. To do that, you have to have done it once by hand, slowly, on numbers small enough to hold in your head.

Take the smallest network that still has everything: one input, one hidden unit with a ReLU, one output, and a squared error against a target. Four parameters. Here are their starting values, and they are the only numbers you need.

x = 2.0 w₁ = 0.5 b₁ = 0.1 w₂ = −1.5 b₂ = 0.4 target y = 1.0 z₁ = w₁·x + b₁ a₁ = ReLU(z₁) z₂ = w₂·a₁ + b₂ L = (z₂ − y)²

The forward pass is four multiplications. The backward pass is the interesting half. It answers one question: how much did each of those four parameters contribute to the loss? It answers it by walking the same path in reverse, multiplying one small derivative at each stop.

Read the backward pass as a single sentence: the gradient at any point is the gradient one step later, multiplied by the local derivative of the step between them. That is the chain rule, and it is the only mathematics in this lesson.

The maths, once
∂L/∂z₂ = 2(z₂ − y) = 2 × (−2.25) = −4.50 ∂L/∂w₂ = ∂L/∂z₂ × a₁ = −4.50 × 1.1 = −4.95 ∂L/∂b₂ = ∂L/∂z₂ × 1 = −4.50 × 1 = −4.50 ∂L/∂a₁ = ∂L/∂z₂ × w₂ = −4.50 × −1.5 = 6.75 ∂L/∂z₁ = ∂L/∂a₁ × ReLU′(z₁) = 6.75 × 1 = 6.75 ∂L/∂w₁ = ∂L/∂z₁ × x = 6.75 × 2.0 = 13.50 ∂L/∂b₁ = ∂L/∂z₁ × 1 = 6.75 × 1 = 6.75

ReLU′ means "the derivative of ReLU". Here z₁ = 1.1 is positive, so ReLU is on its sloping half and that derivative is 1.

Every line is one multiplication, and the thing multiplied is always the local derivative: x for w₁, a₁ for w₂, and 1 for both biases. A bias is added rather than multiplied, so its local derivative is always 1. Its gradient is therefore whatever gradient arrives at that sum, unscaled by the input. That arriving gradient still depends on the whole forward pass. No step in the chain knows anything about the whole network.

Now run the same thing in PyTorch and compare. If your hand numbers and these numbers agree, you understand autograd — there is nothing else inside it.

by_hand.pypython
import torch

x  = torch.tensor(2.0)
w1 = torch.tensor(0.5,  requires_grad=True)
b1 = torch.tensor(0.1,  requires_grad=True)
w2 = torch.tensor(-1.5, requires_grad=True)
b2 = torch.tensor(0.4,  requires_grad=True)
y  = torch.tensor(1.0)

z1 = w1 * x + b1        # 1.1
a1 = torch.relu(z1)     # 1.1
z2 = w2 * a1 + b2       # -1.25
loss = (z2 - y) ** 2    # 5.0625
loss.backward()

print(w1.grad, b1.grad)   # tensor(13.5000) tensor(6.7500)
print(w2.grad, b2.grad)   # tensor(-4.9500) tensor(-4.5000)

Notice the sizes. w₁ is deep in the network and its gradient is 13.50; w₂ is next to the loss and its gradient is −4.95. Gradients are not naturally the same scale in different layers, and that difference is exactly what Adam corrects for, as you saw in Lesson 01.

Common trap

Take one plain gradient-descent step — SGD, stochastic gradient descent, the update rule from Lesson 01 with no momentum — using lr = 0.1. Subtract 0.1 × gradient from each of the four parameters. You get w₁ = −0.85, b₁ = −0.575, w₂ = −1.005 and b₂ = 0.85.

The loss falls from 5.0625 to 0.0225, which looks excellent. Check that number. The new z₁ is −0.85 × 2 − 0.575 = −2.275, so ReLU outputs 0. The output is therefore simply b₂ = 0.85, and the loss is (0.85 − 1)² = 0.0225. The network hit that loss by ignoring its input.

And it is now stuck. ReLU's derivative at −2.275 is 0, so w₁ and b₁ receive a gradient of exactly zero from here on. The unit is dead, permanently, after a single step. A learning rate that is too large does not always produce nan. Sometimes it quietly kills part of your network.

One more gradient, for the project

This example uses squared error. The project uses cross-entropy, so it needs one result the example above does not produce. Write p for the softmax probabilities and t for the one-hot target — a vector of zeros with a single 1 at the correct class. It is t here and not y, because y above is one number, and this is a vector. Then the gradient at the logits collapses to a subtraction:

∂L/∂logits = p − t p = (0.10, 0.70, 0.20), correct class is 0 gradient = (0.10 − 1, 0.70 − 0, 0.20 − 0) = (−0.90, 0.70, 0.20)

Softmax and cross-entropy are built from the same exponentials, and they cancel. Take that on trust for now, or derive it — it is two lines. One warning for the project: if your loss used reduction='mean', divide this gradient by the batch size. Otherwise every number you compute by hand will be too large by exactly that factor.

02 · 3Why the non-linearity is not optional

In the Lesson 01 project you were asked to delete the ReLU and watch the accuracy ceiling appear. Here is why that ceiling exists, in two small matrices you can multiply on paper.

Matrix multiplication is associative: (x @ W1) @ W2 equals x @ (W1 @ W2). The right side has one weight matrix. So a network of stacked linear layers, no matter how deep, computes the same family of functions as a single matrix. Depth costs you memory and time and returns nothing.

Biases do not rescue it either. W₁x + b₁ followed by W₂ gives W₂W₁x + (W₂b₁ + b₂). That is still one matrix and one bias vector, which is still one layer.

collapse.pypython
import torch

x  = torch.tensor([[1.0, -1.0]])
W1 = torch.tensor([[2.0, -1.0], [0.0, 3.0]])
W2 = torch.tensor([[1.0,  4.0], [2.0, 0.0]])

print(x @ W1 @ W2)                # tensor([[-6.,  8.]])
print(x @ (W1 @ W2))              # tensor([[-6.,  8.]])   identical
print(W1 @ W2)                    # tensor([[0., 8.], [6., 0.]])

print(torch.relu(x @ W1) @ W2)    # tensor([[2., 8.]])
# no fixed 2x2 matrix reproduces that for every input

The ReLU clips one intermediate value to zero. That decision depends on the data, so it cannot be folded into a constant matrix. The moment a layer's behaviour depends on which input arrived, depth becomes real capacity.

Remember this

Linear layers give a network its size. Non-linearities give it its depth. Remove the second and the first stops mattering.

02 · 4ReLU, GELU, SwiGLU

Section 3 proved that a bend is required. It did not say which bend, and the choice is not cosmetic. Pick the wrong one and units go silent and stay silent, as the dead unit in section 2 did. An activation function has one job: bend the straight line. Almost any bend does that job. The differences all live in the slope.

ReLU is max(0, x). It is one comparison, and it never saturates on the positive side — the output keeps growing with the input instead of flattening off and killing the gradient. For years it was the default. Its weakness is the flat half you saw in the pitfall above: a unit pushed to the left receives a gradient of exactly zero and has no route back.

GELU is x · Φ(x), where Φ is the cumulative normal distribution — the probability that a standard normal draw lands below x. Instead of a hard switch at zero it fades the input in. SiLU is x · σ(x), where σ is the logistic sigmoid, σ(x) = 1 / (1 + e⁻ˣ), which squashes any number into the range 0 to 1. SiLU has the same character as GELU and is cheaper to evaluate.

"Small but never zero" is the whole argument, so here it is on real values. The slope row is the one that matters:

At x = −2 a ReLU unit gets a gradient of exactly 0 and is finished. GELU and SiLU hand back about −0.09 instead. That is small, but a few hundred steps of it can still drag the unit back into the useful range. On the right the curves converge: at x = 3 GELU is within 0.004 of ReLU, while SiLU is still 0.14 short. So the choice only really bites between roughly −3 and +3 — which is exactly the range a normalised network keeps its activations in.

SwiGLU is different in kind. It is not a curve applied to one number; it is a gate. The layer makes two projections of the same input. A projection is just a matrix multiply, so this is two of them, giving two different vectors. One goes through SiLU, and the two are then multiplied element by element:

SwiGLU(x) = SiLU(xW) ⊙ (xV) ⊙ = element by element

One half decides how much of the other half is allowed through. That gives the layer a multiplicative interaction, which a pointwise curve cannot express. It is not free. An ordinary feed-forward block has two matrices, one projecting up and one projecting back down. SwiGLU needs three: W, V, and the down projection. So implementations shrink the hidden width, meaning the size of the middle layer. Two-thirds of the usual one keeps the parameter count level: 2 048 in place of 3 072.

Which one to use

Default to GELU or SiLU for anything you write in this course. Use SwiGLU inside a transformer feed-forward block, where the extra matrix earns its keep — you build one in Lesson 03. Reach for ReLU only when you need the cheapest possible operation on a device that is counting every cycle.

02 · 5Initialisation: the signal must survive the depth

A badly initialised network does not crash. It trains for an hour, the loss barely moves, and nothing in the output tells you why. This section is the why.

Before training starts, every weight is a random number, and the scale of those numbers is not a detail. Two words first. Standard deviation is the typical distance of a number from the average, and variance is that number squared. The standard deviation is written σ — the same letter that meant "sigmoid" in section 4, and a completely different thing here. In this section, read σ as "typical size".

Consider a layer with n inputs whose weights have standard deviation σ. Each output is a sum of n independent products, so the output's variance is n · σ² · (input variance). ReLU then discards the negative half, which halves the variance again.

Both of those facts are about variance, and what we want to know is the typical size. Typical size is the square root of variance, so take the root: √(n · σ² / 2) = σ · √(n / 2). The signal is multiplied by that factor at every layer. In an eight-layer network it is applied eight times, so small differences compound.

Measured over a whole tensor rather than one number, that typical size has a name: the tensor's RMS, its root mean square. Square every entry, take the mean, take the square root. That is the quantity the code below prints, and the one the project asks you to print layer by layer.

With n = 256, the arithmetic is short and worth doing once:

Row one in full, so you can see where the gain column comes from. 0.02 × √(256 / 2) = 0.02 × 11.31 = 0.226. Applied eight times that is 0.226⁸ = 0.0000069, or about one part in 150 000. Now do row two yourself. You should get 2.26⁸ ≈ 690. The last row is built so the gain is exactly 1: 0.088 × 11.31 = 1.00.

The last row is He initialisation: draw weights with standard deviation √(2 / fan_in), where fan_in is the number of inputs to the layer. The 2 is there to pay for the half of the signal ReLU removes. For activations that keep more of the negative side, the matching rule uses √(1 / fan_in) — the same idea with a different constant.

Measure it yourself rather than trusting the table:

init_scale.pypython
import torch

x = torch.randn(512, 256)                      # 512 examples, 256 features

for std in (0.02, 0.20, (2 / 256) ** 0.5):
    h = x
    for _ in range(8):                         # 8 layers, no bias, ReLU each time
        W = torch.randn(256, 256) * std
        h = torch.relu(h @ W)
    rms = h.pow(2).mean().sqrt().item()
    print(f"std {std:.3f}  ->  signal after 8 layers {rms:.3e}")

# std 0.020  ->  ~7e-06      the signal has vanished
# std 0.200  ->  ~7e+02      the signal has exploded
# std 0.088  ->  ~1e+00      unchanged
Fails silently

Both failures look like "the model does not learn". Neither raises an error. The gradients travel back through the same chain of multiplications. So a vanished forward signal means vanished gradients in the early layers, and those layers keep their random starting values for the whole run. Before you tune the learning rate, print the RMS of the activations at each layer.

02 · 6Writing a layer by hand

You could write a layer as a plain function and keep its weights in a list. Then you would hand that list to the optimizer yourself, move each tensor to the device yourself, and remember every one of them when you saved the model. nn.Module exists so you do not have to.

It is a container with one useful trick. Any tensor you assign to self and wrap in nn.Parameter is registered automatically. It then appears in .parameters(), moves with .to(device), and is picked up by the optimizer. It is also saved by state_dict(). That is the plain dictionary of parameter names to tensors that torch.save writes to disk, and the only thing you actually ship when you share a trained model. Everything else is ordinary Python.

mylinear.pypython
import math
import torch
import torch.nn as nn

class MyLinear(nn.Module):
    def __init__(self, in_features, out_features):
        super().__init__()
        w = torch.randn(in_features, out_features) * math.sqrt(2.0 / in_features)
        self.weight = nn.Parameter(w)                      # learned
        self.bias   = nn.Parameter(torch.zeros(out_features))

    def forward(self, x):                                  # x: (B, in_features)
        return x @ self.weight + self.bias                 # (B, out_features)

class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = MyLinear(784, 128)
        self.fc2 = MyLinear(128, 10)

    def forward(self, x):
        return self.fc2(torch.relu(self.fc1(x.flatten(1))))

print(sum(p.numel() for p in MLP().parameters()))          # 101770

784 × 128 + 128 = 100 480, and 128 × 10 + 10 = 1 290. Together, 101 770 parameters — the same model you trained in Lesson 01, now with no nn.Linear anywhere in it. The bias is added by broadcasting: a tensor of shape (128,) is stretched across all B rows without being copied. B is the batch size, and this course uses that letter for it everywhere, even though PyTorch's own documentation often writes N.

Common trap

nn.Linear stores its weight with shape (out_features, in_features) and computes x @ weight.T. The layer above stores (in_features, out_features). Both are correct, but a state_dict saved from one will not load into the other, and the error message talks about size mismatch rather than about the transpose. Pick one convention and write it in a comment.

02 · 7Convolution: the same detector everywhere

An MLP treats a picture as a flat list of 784 numbers. That throws away the single most useful fact about an image: pixels near each other belong together, and a shape means the same thing wherever it appears. A convolution keeps both facts.

Five words carry the whole idea:

  • Kernel — a small block of weights, usually 3 × 3. It is the detector.
  • Stride — how far the kernel jumps between positions. Stride 2 halves the output size.
  • Padding — a border of zeros added around the input, so the output can keep the input's size.
  • Channels — the depth of the input and the number of kernels. A 3 × 3 kernel on a 3-channel image is 3 × 3 × 3 = 27 weights, and 32 such kernels give 32 output channels.
  • Feature map — the output of one kernel: "where in this picture did my detector fire?"
H_out = (H_in + 2·padding − kernel) / stride + 1 (integer division)

The saving comes from weight sharing. A dense layer mapping a 28 × 28 image to a 26 × 26 output would need 784 × 676 = 529 984 weights. Each of those weights would learn about one pixel position only. One 3 × 3 kernel needs 9 weights and a bias, and it applies at every position. It also generalises. A detector trained on edges in the top-left corner works in the bottom-right corner for free.

cnn_shapes.pypython
import torch
import torch.nn as nn

x    = torch.randn(32, 1, 28, 28)          # B, C, H, W
c1   = nn.Conv2d(1, 32, kernel_size=3)     # 1*32*3*3 + 32  =    320 params
c2   = nn.Conv2d(32, 64, kernel_size=3)    # 32*64*3*3 + 64 = 18 496 params
pool = nn.MaxPool2d(2)

h = pool(torch.relu(c2(torch.relu(c1(x)))))
print(h.shape)                             # torch.Size([32, 64, 12, 12])
print(h.flatten(1).shape)                  # torch.Size([32, 9216])

28 → 26 → 24, then the pool halves it to 12. Now count the parameters of the whole classifier, and look at where they are:

Two different resources

More than 97% of this model's parameters sit in one dense layer, while nearly all of the arithmetic happens in the two convolutions. Parameters and compute are separate budgets. Part III of this course shrinks the first — quantization makes weights smaller — while Lesson 08 attacks the second. Confusing the two is why people are surprised when a smaller model is not faster.

02 · 8Pooling, and two kinds of normalisation

Two more parts and the classifier is complete. Without pooling, every layer works at full resolution and the dense layer that follows explodes in size. Without normalisation, the careful signal scale of section 5 lasts about a hundred steps and then drifts away.

Pooling shrinks a feature map by summarising small neighbourhoods. MaxPool2d(2) takes each 2 × 2 block and keeps the largest value, turning 24 × 24 into 12 × 12. It has no parameters. It buys two things. First, less work in every layer that follows. Second, a little tolerance to shift: moving a feature by one pixel often does not change which value is the largest. Many modern architectures replace it with a stride-2 convolution, which does the same shrinking but learns how.

Normalisation is section 5's problem solved over and over instead of once. He initialisation sets the signal size correctly on step zero. Training then moves the weights and the sizes drift again. A normalisation layer resets them on every forward pass.

What it computes is short. Take a group of numbers, subtract their mean, divide by their standard deviation. The group now has mean 0 and typical size 1. Then multiply by a learned gain and add a learned shift, so the layer can undo the normalisation if that turns out to be what it wants. Try it on real numbers. The row (2, 4, 4, 4, 5, 5, 7, 9) has mean 5 and standard deviation 2. It normalises to (−1.5, −0.5, −0.5, −0.5, 0, 0, 1, 2): same order, new scale.

Batch normalisation and layer normalisation differ in one thing only: which group they average over. Batch normalisation averages each feature across all the examples in the batch, so an example's output depends on the other examples travelling with it. At evaluation time there may be no batch to average over, so it falls back on running statistics. Those are a mean and a variance accumulated over training, stored inside the model, and reused at inference. Batch norm also behaves badly with very small batches, and is awkward for sequences of different lengths.

Layer normalisation averages each example across its own features. It never looks at its neighbours, works with a batch of one, and needs no running statistics. That independence is why convolutional vision models mostly use batch norm. Every transformer normalises per example instead — layer norm, or its cheaper cousin RMSNorm, which is the one Lesson 03 builds.

With that, you have one of the two halves of a transformer block. A block is attention plus an MLP, with a normalisation before each and a residual connection around each. A residual connection means the block's input is added back onto its output — x + f(x) — rather than replaced, so the gradient always has a short path home. Lesson 03 shows why a deep stack cannot train without it. The MLP is the layer you wrote in section 6, with SwiGLU in the middle instead of ReLU. Lesson 03 adds the piece that is missing.

Check yourself

Hold ∂L/∂z₁ at 6.75, but suppose the input x were 3.0 instead of 2.0. What are ∂L/∂w₁ and ∂L/∂b₁ now?

Because z₁ = w₁·x + b₁, the local derivative ∂z₁/∂w₁ is x, so the weight gradient scales with the input: 6.75 × 3.0 = 20.25. But ∂z₁/∂b₁ is 1 whatever x is. So while ∂L/∂z₁ is held fixed, only the weight gradient moves. Note the word held. Change x for real and both gradients move, because ∂L/∂z₁ itself changes. With x = 3.0 the forward pass gives z₁ = 1.6 and z₂ = −2.0, so ∂L/∂z₁ becomes 9.0. The two gradients are then 27.0 and 9.0. Only the local derivative of a bias ignores the input.

You remove every activation function from a 5-layer MLP with hidden widths 512, 512, 512, 512. What is the model now equivalent to?

Five matrix multiplies in a row can be replaced by their product, which is one matrix. The model still trains and the loss still falls — it just cannot represent anything a single matrix cannot represent, so it plateaus early.

You apply nn.Conv2d(3, 16, kernel_size=5, padding=2) to a batch of 32 × 32 colour images. How many parameters does it have, and what shape comes out?

Each of the 16 output channels needs a kernel spanning all 3 input channels: 3 × 5 × 5 = 75 weights, plus one bias. 16 × 75 = 1 200, plus 16 biases = 1 216. For the shape, put the numbers in the formula from section 7: (32 + 2 × 2 − 5) / 1 + 1 = 32. Padding 2 with a 5 × 5 kernel keeps the size exactly. The input size never enters the parameter count — that is the point of weight sharing.

Key words from this lesson
Neuron also: unit
One weighted sum of the inputs, plus a bias, plus a non-linear function.
Bias /ˈbaɪəs/
The one number in a neuron that is added rather than multiplied. It shifts the decision away from zero.
Backpropagation often: backprop
Walking the recorded operations in reverse and multiplying local derivatives, to get a gradient for every parameter.
Local derivative
How much one operation's output changes when its own input changes. Each operation knows only this.
Non-linearity also: activation function
Any function whose graph is not a straight line. Without one between two linear layers, the pair collapses into a single layer.
Dead unit also: dead ReLU
A neuron whose sum is always negative, so ReLU outputs zero, the gradient is zero, and it can never recover.
Initialisation
The scale of the random numbers a network starts from. It decides whether the signal survives the depth.
Kernel also: filter
The small block of weights a convolution slides over its input. Usually 3 × 3.
Feature map
The output of one kernel over the whole input: a picture of where that detector fired.
Weight sharing
Using the same weights at every position, so the parameter count does not grow with the size of the input.
Normalisation
Subtract the mean of a group of numbers, divide by their standard deviation, then apply a learned gain and shift.
Layer normalisation also: LayerNorm
Rescaling each example using only its own features, so the result never depends on the other examples in the batch.
Residual connection also: skip connection
Adding a block's input back onto its output, x + f(x), so the gradient always has a short path back through the network.
