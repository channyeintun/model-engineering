03

Inside a Transformer

A decoder-only transformer is one function: integers in, a probability for every possible next token out. This lesson opens that function and follows the shapes through, until nothing is left that you could not write yourself.

03 · 1From text to integers

A network only consumes numbers, and text is a string. The tokenizer stands between them. It is not part of the model and is not trained by gradient descent: it is a fixed dictionary, built once, before training starts.

There are three ways to split text, and two of them are bad. One character per token gives a tiny vocabulary but very long sequences, and attention cost grows with the square of sequence length. One word per token gives short sequences but an endless vocabulary: every typo becomes an unknown word. Subwords are the compromise everybody uses.

Byte pair encoding (BPE) builds the dictionary with an algorithm you could write in an afternoon. Start with single symbols. Count every adjacent pair in a large corpus. Merge the most frequent pair into one new symbol and write down the merge rule. Repeat until the vocabulary is the size you asked for. Prose is easy to nod along to, so run the loop by hand.

bpe by handtrace
corpus       low low lower
start        every character is its own symbol
             l o w   l o w   l o w e r

count pairs  (l,o) 3    (o,w) 3    (w,e) 1    (e,r) 1
merge 1      (l,o) is joint first, take it  ->  new symbol "lo"
             lo w   lo w   lo w e r

count pairs  (lo,w) 3   (w,e) 1    (e,r) 1
merge 2      (lo,w) wins  ->  new symbol "low"
             low   low   low e r

merge list   [ (l,o), (lo,w) ]          <- this is the whole tokenizer
vocabulary   l o w e r  +  lo  low      <- 5 characters plus 2 merges

encoding replays the merge list in order, first every (l,o), then every (lo,w):
   "low"    ->  low            1 token,  because it was frequent
   "lower"  ->  low + e + r    3 tokens, because it was not

That is the whole trade in miniature. A real tokenizer runs the same loop with 50,000 merges.

Byte-level BPE, introduced with GPT-2, makes one extra choice: the starting alphabet is the 256 byte values, not characters. Any text becomes bytes first, so the tokenizer encodes Chinese, emoji and source code without ever producing an unknown token. The price: one non-ASCII character can take two to four tokens.

tokenize.pypython
from transformers import AutoTokenizer

tok = AutoTokenizer.from_pretrained("HuggingFaceTB/SmolLM3-3B")

ids = tok("Tokenizers split rare words.")["input_ids"]
print(len(tok))                       # the vocabulary size
print(ids)                            # a list of integers
print(tok.convert_ids_to_tokens(ids)) # the pieces those integers stand for
print(tok.decode(ids))                # exactly the original string, spaces included

Run that on your own text. Two habits follow. First, the rule of thumb: English text is roughly 4 characters per token. A word plus its space averages 5 characters, so a 2,000-word article is about 10,000 characters, and 10,000 / 4 = 2,500 tokens. The same rule reversed: 1 token ≈ 0.8 words.

Second, the space in front of a word usually belongs to the token: " split" and "split" are different ids. End a prompt with a trailing space and the model must continue a token that normally begins with one — a shape it has almost never seen. Completions get noticeably worse. This is why chat templates never leave a space before the answer.

Common trap

Token counts are not comparable between models. The same sentence can be 18 tokens for one tokenizer and 24 for another. Any metric that depends on tokens — context length, price per token, perplexity (Lesson 04 defines it) — is only meaningful next to the tokenizer that produced it.

03 · 2The embedding table, and what vocabulary costs

An embedding is a lookup table with shape (V, d). V is the vocabulary size. d is the model width, usually written d_model. Token id 4,471 means "give me row 4,471". Input shape (B, T) of integers becomes output shape (B, T, d) of floats. That is the entire operation. The rows start random and are trained like any other weight.

Vocabulary size is a real engineering decision: the table is V × d numbers.

A larger vocabulary means fewer tokens per sentence, so shorter sequences, less attention work and better coverage of languages other than English. It also means a larger table. Gemma 4 E2B has d = 1,536 and a 262,144-token vocabulary, so the embedding alone is about 403 million parameters — larger than several complete "1B" models.

Worth knowing

At the other end of the model sits a matrix of the same shape: the output head that turns the final d numbers into one score per vocabulary entry. Nearly every small model ties these two together and stores one matrix instead of two — tie_word_embeddings: true. It is true for Qwen3-0.6B, Qwen3.5-2B, SmolLM3-3B, Llama 3.2 1B and 3B, and Phi-4-mini. With a wide vocabulary and a narrow body, this halves a very large number.

03 · 3Attention has no idea what order the tokens are in

This is the fact that surprises people. Attention is permutation-equivariant: shuffle the input tokens and the outputs come back in the same shuffled order, unchanged. "dog bites man" and "man bites dog" give the same set of vectors. Position has to be injected on purpose.

The original 2017 transformer added a fixed pattern of sines and cosines to the embedding. GPT-2 and BERT — an encoder-only model, the kind Section 7 explains — learned a second table, (max_len, d), and added that. Both have problems: the sinusoidal version extrapolates badly past the training lengths, and the learned version caps context at max_len.

RoPE — rotary position embedding — is what every model in this course uses. It does not add anything. It takes each pair of adjacent numbers inside q and k and treats the pair as a point in a plane. Then it rotates that point by an angle proportional to the token's position.

The maths, once
θi = base−2i/dh rotate pair i at position m by m·θi after rotation: qm · kn depends only on (m − n) m n the positions of the query token and the key token θi the rotation angle for pair i · dh the head dimension

That last line is the whole trick, and the one claim here you should not take on faith.

So check it. Take one pair, so each vector is a point in a plane, and reach for a calculator.

rope by handtrace
q = (1, 0) at position m,  k = (1, 0) at position n,  theta = 0.1 rad per position
rotating (1, 0) by an angle a gives (cos a, sin a)

m = 5,  n = 3     q rotated by 5*0.1 = 0.5 rad  -> (0.878, 0.479)
                  k rotated by 3*0.1 = 0.3 rad  -> (0.955, 0.296)
                  dot = 0.878*0.955 + 0.479*0.296 = 0.980

m = 12, n = 10    q rotated by 1.2 rad          -> (0.362, 0.932)
                  k rotated by 1.0 rad          -> (0.540, 0.841)
                  dot = 0.362*0.540 + 0.932*0.841 = 0.980

why it must be so:  dot of two unit vectors at angles a and b  =  cos(a - b)
                    here that is cos(m*theta - n*theta) = cos((m - n)*theta)
                    both rows have m - n = 2, so both give cos(0.2) = 0.980

and for any q and k:  each one is turned by its own position, so the angle
                      between them ends up (m - n)*theta plus whatever angle
                      they started with. The cancellation does not need q = k.

Both tokens moved 7 positions down the sequence. The score did not move at all.

Two tokens two positions apart contribute the same score wherever they sit. Position becomes relative, for free, inside the dot product — no extra parameters, no length limit.

rope.pypython
import torch

def rope_cache(T, d_head, base=10000.0, device=None):
    inv = 1.0 / (base ** (torch.arange(0, d_head, 2, device=device).float() / d_head))
    ang = torch.outer(torch.arange(T, device=device).float(), inv)   # (T, d_head/2)
    return ang.cos(), ang.sin()

def apply_rope(x, cos, sin):          # x: (B, H, T, d_head)
    x1, x2 = x[..., 0::2], x[..., 1::2]
    cos, sin = cos[None, None], sin[None, None]
    return torch.stack([x1 * cos - x2 * sin, x1 * sin + x2 * cos], dim=-1).flatten(-2)

The base value, rope_theta in config files, decides how fast the angles turn. A larger base means slower rotation, and so a longer usable context. Llama 3.2 uses 500,000; Qwen3-0.6B 1,000,000; SmolLM3-3B 5,000,000; Qwen3.5-2B 10,000,000. When a model card advertises a long context, that number is part of the reason.

Two variations in 2026 configs look like contradictions until you see the reason. Partial RoPE rotates only a fraction of each head. Qwen3.5-2B sets partial_rotary_factor: 0.25, leaving three quarters of every head free of position — room for facts that mean the same thing wherever the token sits. NoPE layers — no positional embedding — switch RoPE off entirely; SmolLM3-3B does this every fourth layer. An unrotated layer cannot be thrown off by an angle it never saw in training, and the RoPE layers around it still supply the order.

03 · 4Attention, one matrix at a time

Start with what is broken. After the embedding, every token is described by its own vector and nothing else. Take "The cat sat on the mat and it". The vector for "it" is the same one it would have in any other sentence, with no trace of the cat. Something must let "it" read "cat", and the model must learn which word to reach for, because no rule tells it in advance.

Attention is that step: each token looks at the other tokens and pulls in what is relevant to it. Every token produces three vectors from the same input, through three different learned matrices:

  • query q — what this token is looking for.
  • key k — what this token offers to others.
  • value v — what this token actually hands over if chosen.
  • output Wo — one more learned matrix at the end, which mixes the heads' results back into a single vector.

The comparison is a dot product: large when two vectors point the same way, near zero when unrelated, negative when they point apart. So q · k is a similarity score, and one query against all keys gives a row of them.

Remember this
Attention(Q, K, V) = softmax( QKᵀ / √dh ) V Q K V activations, shape (B, H, T, d_h) Wq Wk Wv Wo learned matrices, shape (d, ·)

Everything else here is packaging around that line.

Now the shapes. Every letter in this lesson is named here, once. B is the batch size. T is the sequence length in tokens. d is the model width, d_model. H is the number of query heads. G is the number of key/value heads, and G = H in plain multi-head attention. d_h = d / H is the head dimension, d_head in code — unless a config sets head_dim itself, which Section 8 covers.

StepShapeWhat it holds
x(B, T, d)one vector per token
q, k, v after reshape(B, H, T, d_h)each head gets its own slice
scores = q @ k.transpose(-2,-1)(B, H, T, T)every token against every token
attn = softmax(scores)(B, H, T, T)each row sums to 1
out = attn @ v(B, H, T, d_h)a mixture of values
out @ Wo(B, T, d)back onto the block's main vector — the residual stream of Section 6

The (B, H, T, T) row is the expensive one. It grows with the square of the sequence length. That is why long context is hard, and why Section 5 works so hard at making the stored keys and values smaller.

Why divide by √dh

Assume the entries of q and k have mean 0 and variance 1. Their dot product sums d_h such products, so it has variance d_h and standard deviation √d_h. At a head dimension of 128 that is a spread of roughly ±11.

Feed numbers that far apart into softmax and the result is almost one-hot: one weight near 1, the rest near 0. In Lesson 01 you saw that a probability of 1 on the right answer gives a loss of 0, and therefore no gradient. The same thing happens here, in the middle of the network: the softmax saturates, the gradient through it becomes almost zero, and training stalls. Dividing by √d_h restores unit variance. PyTorch does this by default: scale = 1 / sqrt(query.size(-1)).

The causal mask

A language model predicts the next token. If position 5 could read position 6, it would be reading the answer. So before the softmax, every score whose key comes after its query is set to negative infinity.

The exponential of negative infinity is 0, so those weights are exactly zero. Everything on and below the diagonal stays, and each row still sums to 1 over the part it may see.

This mask is what makes one forward pass so productive. Row 0 predicts token 1 from one token of context; row 7 predicts token 8 from eight. One pass over length T produces T separate training signals at once, at no extra cost. That is why next-token prediction scales the way it does.

The mistake that still trains

Apply the mask after softmax — zeroing the upper triangle instead of setting it to −inf beforehand — and nothing crashes. The rows stop summing to 1, the model leaks a little of the future through the normalisation, and the loss curve looks almost normal. You lose days to this. Mask first, softmax second, always.

attention.pypython
import math, torch, torch.nn.functional as F

def attention(q, k, v, causal=True):
    """q, k, v: (B, H, T, d_head) -> (B, H, T, d_head)"""
    d_head = q.size(-1)
    scores = (q @ k.transpose(-2, -1)) / math.sqrt(d_head)       # (B, H, Tq, Tk)
    if causal:
        Tq, Tk = q.size(-2), k.size(-2)
        # tril(0) is the plain lower triangle. The offset Tk - Tq keeps it correct
        # when q is shorter than k, which happens once you decode one token
        # against a cache (Lesson 04). With Tq == Tk the offset is 0.
        keep = torch.ones(Tq, Tk, dtype=torch.bool, device=q.device).tril(Tk - Tq)
        scores = scores.masked_fill(~keep, float("-inf"))        # mask BEFORE softmax
    return torch.softmax(scores, dim=-1) @ v

q, k, v = torch.randn(3, 2, 4, 16, 64).unbind(0)                 # B=2, H=4, T=16, d_h=64
mine = attention(q, k, v)
ref  = F.scaled_dot_product_attention(q, k, v, is_causal=True)
print(torch.allclose(mine, ref, atol=1e-5))                      # True

That is the whole mechanism. In production you call F.scaled_dot_product_attention instead, because it never builds the (B, H, T, T) matrix in memory. Same function — and now you can prove it.

03 · 5Heads, and the size of the KV cache

One softmax row is one weighted average, so it expresses one relation per position and no more. Multi-head attention runs several side by side. The important detail: heads do not make the layer wider. The d numbers are cut into H slices of d_h = d / H. Each slice gets its own Wq, Wk and Wv, and the outputs are laid end to end again. The arithmetic is unchanged.

Heads specialise on their own, with nobody telling them to. Researchers have found previous-token heads, syntax heads, and induction heads that complete a pattern: having seen [A][B] earlier, when [A] returns they push [B]. That last one is much of why these models copy a name or a format from earlier in your prompt.

Multi-head, grouped-query and multi-query

Now the part that decides whether your model fits on a phone. Everything so far computes all T positions in one parallel pass. Generation does not work that way: you produce token 1, append it, run the model again, produce token 2, and so on — the loop Lesson 04 builds. Unaided, each new token re-runs attention over the whole prefix from scratch.

So the keys and values are stored instead. That store is the key/value cache, written KV cache. It grows linearly with the conversation, and its size is set by the number of key/value heads — not query heads.

bytes = 2 × n_layers × n_kv_heads × d_head × seq_len × bytes_per_element 2 one K and one V n_kv_heads key/value heads per layer, the G of Section 4 d_head the head dimension, dh bytes_per_element 2 for FP16 (a 16-bit float is 2 bytes), 4 for FP32

Memorise that line. Nothing in it depends on the query heads, so decouple the two: many query heads, few key/value heads, each group of queries sharing one pair. That is grouped-query attention (GQA), the default in almost every 2026 model. It sits between two extremes. Multi-head attention (MHA) gives every query head its own key/value head, so G = H. Multi-query attention (MQA) shares one across all of them, so G = 1.

VariantQ headsKV headsCache sizeQuality
MHA — multi-headHH1×best
GQA — grouped-queryHGG/Hclose to MHA
MQA — multi-queryH11/Hnoticeable drop

Put real numbers on it. Llama 3.2 1B has 16 layers, head dimension 64, 32 query heads and 8 key/value heads, and stores its cache in FP16. Every factor below comes from that sentence:

2 (K and V) × 16 layers × 8 KV heads × 64 per head × 2 bytes = 32,768 bytes = 32 KiB per token

An 8,192-token context therefore costs 8192 × 32 KiB = 256 MiB. With plain multi-head attention it would store 32 KV heads instead of 8, four times as many. That same context would then cost 1 GiB, on top of the weights.

Gemma 4 E2B goes all the way to one KV head, true MQA, because it is built for a device. PyTorch supports the sharing directly: F.scaled_dot_product_attention(..., enable_gqa=True) repeats the key and value heads internally, and requires n_q_heads % n_kv_heads == 0.

attn_module.pypython
import torch.nn as nn, torch.nn.functional as F

class Attention(nn.Module):
    def __init__(self, d, n_head, n_kv_head):
        super().__init__()
        self.nh, self.nkv, self.dh = n_head, n_kv_head, d // n_head
        self.wq = nn.Linear(d, n_head    * self.dh, bias=False)
        self.wk = nn.Linear(d, n_kv_head * self.dh, bias=False)
        self.wv = nn.Linear(d, n_kv_head * self.dh, bias=False)
        self.wo = nn.Linear(n_head * self.dh, d, bias=False)

    def forward(self, x, cos, sin):
        B, T, _ = x.shape
        q = self.wq(x).view(B, T, self.nh,  self.dh).transpose(1, 2)
        k = self.wk(x).view(B, T, self.nkv, self.dh).transpose(1, 2)
        v = self.wv(x).view(B, T, self.nkv, self.dh).transpose(1, 2)
        q, k = apply_rope(q, cos, sin), apply_rope(k, cos, sin)
        o = F.scaled_dot_product_attention(q, k, v, is_causal=True, enable_gqa=True)
        return self.wo(o.transpose(1, 2).reshape(B, T, -1))
Common trap

Passing both attn_mask and is_causal=True to F.scaled_dot_product_attention raises an error. Pick one. If you need padding as well as causality, build the combined boolean mask yourself and pass it as attn_mask with is_causal=False.

03 · 6The rest of the block

Attention moves information between positions, but does no thinking within one — every output is a weighted average of values. The second half of the block does that work, and holds most of the parameters.

That second half is the feed-forward network, also written FFN. This course usually calls it the MLP, short for multi-layer perceptron. Classically it is two matrices with a non-linear activation between them: d → 4d → d. Call that inner width d_ff, the number of neurons in the middle. It is the only shape in a block not fixed to a multiple of d.

Modern models use SwiGLU: three matrices and a gate, written down( SiLU(gate(x)) * up(x) ). Here SiLU(z) = z · sigmoid(z), and sigmoid(z) = 1 / (1 + e−z) is the S-curve that squashes any number into 0…1. So SiLU — sigmoid linear unit — leaves large positive values almost untouched and pushes negative ones toward zero. The multiply lets one path decide how much of the other gets through.

Three matrices instead of two means more parameters at the same d_ff. The original SwiGLU papers kept the total fixed with d_ff ≈ (2/3) · 4d. Modern models often do not bother — compare the d_ff column below with 4 · d_model — and accept a larger MLP.

Around both sub-layers sits the structure that makes depth possible.

The line running through the block is the residual stream. Its shape is (B, T, d) from the embedding to the final norm, and it is never replaced — only added to. In Lesson 02 you watched gradients shrink through a chain of matrix multiplies. The residual path has no matrix on it, so the gradient reaches layer 1 intact. That is the only reason a 36-layer network trains at all. Normalisation then keeps the numbers on the stream in a sane range.

LayerNorm(x) = γ · (x − mean) / √(var + ε) + β 2d parameters RMSNorm(x) = γ · x / √( mean(x²) + ε ) d parameters γ a learned scale, one number per channel — d of them β a learned shift, one number per channel — d more ε a tiny constant, 1e-6, that stops a divide by zero. Not learned.

Now the counts are visible rather than asserted. LayerNorm learns γ and β, so 2d. RMSNorm drops the mean subtraction and keeps only γ, so d. It is around 10–15% faster and works just as well. Every model in this lesson uses it, with rms_norm_eps = 1e-6. Where the norm sits matters more than which norm you pick.

Post-norm (2017)

  • x = Norm(x + sublayer(x))
  • The norm sits on the residual stream.
  • Will not train at all unless the learning rate is raised slowly from near zero over the first few hundred steps — the warmup of Lesson 04.
  • Becomes unstable as depth grows.

Pre-norm (standard today)

  • x = x + sublayer(Norm(x))
  • The norm sits inside the branch.
  • The stream itself stays untouched, so gradients travel cleanly.
  • Trains at 30+ layers without tricks.
block.pypython
import torch, torch.nn as nn, torch.nn.functional as F

class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__(); self.eps = eps
        self.weight = nn.Parameter(torch.ones(d))
    def forward(self, x):
        return self.weight * x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)

class SwiGLU(nn.Module):
    def __init__(self, d, d_ff):
        super().__init__()
        self.gate = nn.Linear(d, d_ff, bias=False)
        self.up   = nn.Linear(d, d_ff, bias=False)
        self.down = nn.Linear(d_ff, d, bias=False)
    def forward(self, x):
        return self.down(F.silu(self.gate(x)) * self.up(x))

class Block(nn.Module):                       # pre-norm decoder block
    def __init__(self, d, n_head, n_kv_head, d_ff):
        super().__init__()
        self.n1, self.attn = RMSNorm(d), Attention(d, n_head, n_kv_head)
        self.n2, self.mlp  = RMSNorm(d), SwiGLU(d, d_ff)
    def forward(self, x, cos, sin):
        x = x + self.attn(self.n1(x), cos, sin)   # edit the stream, never replace it
        x = x + self.mlp(self.n2(x))
        return x

That block is stacked n_layers times with nothing between the copies. Everything else — the embedding at the front, a final RMSNorm and the output head at the back — is a few lines. Here is the shared 2026 recipe in practice:

03 · 7Encoder, decoder, and both

"Transformer" names a family, and the masking separates its members.

TypeMaskTrained toExamples
Encoder-onlynone — every token sees every tokenfill in hidden wordsBERT, RoBERTa, ModernBERT, embedding models
Decoder-onlycausalpredict the next tokenGPT, Llama, Qwen, Gemma, Phi, SmolLM
Encoder-decodernone in the encoder, causal plus cross-attention in the decoderturn one sequence into anotherT5 (text to text), Whisper (speech to text), NLLB (translation)

An encoder is better at understanding a fixed text, because every token has the full context on both sides. It cannot generate, having already seen the answer. A decoder can, and predicting the next token turns out to be rich enough to learn understanding as a side effect. Cross-attention is ordinary attention with the queries from the decoder and the keys and values from the encoder. You meet it again in Lesson 11, because Whisper is this shape.

Everything else in this course is decoder-only.

03 · 8Counting a tiny GPT

Every model on Hugging Face ships a config.json. Map its keys onto the letters of Section 4 and you can predict the size before downloading a weight:

That is Llama 3.2 1B. One warning before the arithmetic: head_dim is the head width, and where a config lists it, it wins over d / H. Here the two agree at 64. Qwen3-0.6B, in the table above, sets head_dim to 128 where d / H would give 64. That is why it counts about 596 M parameters and is called 0.6B, not the 508 M that d / H predicts.

Per layer, no biases:

attn = d·(H·d_h) + 2·d·(G·d_h) + (H·d_h)·d mlp = 3·d·d_ff (gate, up, down) norm = 2·d (two RMSNorms)

The three attn terms are Wq, then Wk and Wv together, then Wo. Only the middle one uses G — which is exactly why grouped queries shrink attention and leave the MLP alone. Then add V·d once for the tied embedding and d for the final norm.

count.pypython
def gpt_params(d=384, n_layer=6, n_head=6, n_kv_head=6, d_ff=1024, vocab=8192):
    d_h  = d // n_head
    attn = d * (n_head * d_h) + 2 * d * (n_kv_head * d_h) + (n_head * d_h) * d
    mlp  = 3 * d * d_ff
    norm = 2 * d
    per_layer = attn + mlp + norm
    total = n_layer * per_layer + vocab * d + d      # tied embedding, final norm
    return per_layer, total

print(gpt_params())            # (1770240, 13767552)
print(gpt_params(n_kv_head=2)) # GQA: fewer parameters and a 3x smaller KV cache

Just under 14 million parameters, under 28 MB in FP16 at 2 bytes each. The project uses a 65-character vocabulary instead, so its embedding is 65 · 384 = 24,960 and the whole model is about 10.65 M. The blocks are identical; only the embedding changed.

Two consequences. First, in this model the MLP holds about twice as many parameters as attention, so d_ff is the first knob for a smaller model. In a grouped-query model the gap is far wider. Llama 3.2 1B has roughly 10.5 M attention parameters per layer against 50.3 M in the MLP, because G = 8 shrinks attention and nothing shrinks the MLP. Second, the embedding is 23% of this model: a small model with a large vocabulary spends most of itself on a lookup.

How long the training will take

Training compute is about 6 × N_nonembedding × D_tokens FLOPs. A FLOP is one floating-point operation — one multiply or one add. The 6 is two operations forward and four backward, per parameter per token. N_nonembedding is the parameter count without the embedding table: 10.6 million here, not 13.8 million, because a lookup does no arithmetic. Over 100 million tokens that is 6 × 10.6e6 × 1e8 ≈ 6.4e15 FLOPs. A laptop GPU gives roughly 2 TFLOP/s — 2 trillion operations per second — so 6.4e15 / 2e12 ≈ 3,200 s, under an hour. You can genuinely train this yourself.

Check yourself

You increase the head dimension from 64 to 256 and forget to change the scaling factor, leaving / sqrt(64) in the code. What happens?

The dot product of two d_h-dimensional vectors has standard deviation √d_h, so at 256 the scores spread about twice as wide as the code assumes. Softmax saturates, and a saturated softmax passes almost no gradient — the same effect you met in Lesson 01 with a confident, correct classifier.

A model has 24 layers, 32 query heads, 8 key/value heads and a head dimension of 128. You switch it from GQA to plain MHA and change nothing else. What happens to the KV cache?

Cache size is 2 × layers × kv_heads × d_head × tokens × bytes. Only kv_heads changes, from 8 to 32, so the cache grows by a factor of 4. The number of query heads never appears in the formula.

Your causal model reaches a training loss of 0.4 in a few hundred steps, far below anything you expected, but the text it generates is nonsense. What is the most likely cause?

A loss that is far too good, far too fast, almost always means the model can see the answer. Without the mask, position t attends to position t+1 during training. At generation time that token does not exist yet, so the model has learned a task it can never perform.

A config reads hidden_size 2048, num_hidden_layers 28, num_attention_heads 16, num_key_value_heads 8, head_dim 128, intermediate_size 6144, vocab_size 151936, tie_word_embeddings true. Roughly how many parameters?

Here head_dim and d / H agree at 128, so attention is 2048·2048 + 2·2048·1024 + 2048·2048 = 12.58 M. The MLP is 3 · 2048 · 6144 = 37.75 M, and the norms add 4,096. That is 50.34 M per layer, so 1,409 M over 28 layers. The tied embedding adds 151,936 · 2048 = 311 M, giving 1,720,567,808 — about 1.72 B. The wrong answers count the embedding twice (2.03), forget the gate matrix (1.37), or read the embedding alone (0.31).

You swap a model's 32,000-entry tokenizer for a 262,144-entry one and change nothing else. The width is d = 1,536 and the embedding is tied. What have you bought, and what has it cost?

The table is V × d: 32,000 · 1,536 = 49,152,000 against 262,144 · 1,536 = 402,653,184. Tying stores it once, and one copy is already the whole cost. A wider vocabulary does cut tokens per sentence, which is the real win, because attention grows with T². V never enters attention's cost — it enters the parameter count, which is why Gemma 4 E2B spends 403 M on a lookup.

Key words from this lesson
Tokenizer also: BPE, SentencePiece
A fixed dictionary splitting text into pieces, each mapped to an integer. Built before training, never learned by gradient descent.
d_model also: model width, hidden size
How many numbers describe one token inside the model. Nearly every shape here contains it.
d_ff also: intermediate size
The inner width of the feed-forward network — the one shape in a block not tied to d_model.
Query, key, value
Three vectors made from one token by three learned matrices: what it wants, what it offers, what it hands over.
Causal mask
Setting every future token's score to negative infinity before the softmax, so a position can never read ahead.
Head /hed/
One slice of the model width running its own attention. Several heads express several relations at once.
GQA grouped-query attention
Query heads sharing one key/value head, so the cache shrinks while quality stays close to multi-head attention (MHA). One shared head for all of them is MQA, multi-query attention.
RoPE rotary position embedding
Rotating pairs of numbers inside the query and key by an angle set by position, so the dot product depends only on the distance between two tokens.
RMSNorm
Dividing a vector by the root mean square of its entries, then scaling by one learned number per channel. Half of LayerNorm's parameters.
Residual stream
The vector running unchanged through every block, shape (B, T, d). Each sub-layer reads a copy and adds a result back.
SwiGLU
The gated feed-forward network of modern models: two matrices up, one a gate, one back down.
